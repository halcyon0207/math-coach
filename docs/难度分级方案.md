## 一、三档的定义

| 档 | 一句话 | 孩子要做什么 | 解锁线（该知识点掌握度） |
|---|---|---|---|
| **基础** | 和课本例题长得一样的题 | 一步一步算，一步就能到答案 | 0（默认就出） |
| **巩固** | 变式、逆向 | 换个样子认出它，或者反着推 | **0.45** |
| **挑战** | 两步串联、说理 | 把两件事接起来，或者讲清为什么 | **0.70** |

数字定义在 `js/knowledge.js` 的 `TIERS` 里，档位**不写在模板上**——
模板只写一个 `difficulty`（本来就有、手工调过的一列数），档位由它查出来：

```js
Knowledge.tierOf(t.difficulty)   // → { level, key, name, unlock, tip }
```

这样只有**一份**难度数字。如果另外再给每个模板标一次"这是基础题"，
两份账迟早会打架（改了一个忘了另一个），打架之后没人知道该信谁。

## 二、为什么是"解锁"而不是"自动升难"

这是整件事的关键，也是你提的那个要求的正面回答：

> "全部是最基础的水平，练几次就没挑战了" —— 但"最重要的还是夯实基础"

这两句不冲突，冲突的是**随机撒难题**这种做法。引擎里原本已经有一套连续自适应难度
（`difficultyBase + difficultyShift*0.12`，连错降、连对且掌握度高才升），
它调的是**在同一条题族里挑哪一题**；档位门禁调的是**这个知识点的题池里允许存在哪些题**。
两件事叠在一起：

- 掌握度 0.2 的孩子进场 → 只见到基础档 → 做对、攒证据 → 涨到 0.45 自动多出巩固档
- 掌握度 0.9 → 三档全开，组卷的压轴题（第 10 题）会挑**已解锁里最难的那一道**

如果只是把难题混进随机池，最先碰到它的永远是错得最多的那个孩子，
他的掌握度被打下去，支架撤得更快 —— 分级反而变成打击。

## 三、每一档是从哪份教案来的

下面每条都对着教案原话。左列是教材/教案里的分层，右列是本项目落在的模板。

### 第五单元 常见的数量关系（单价、速度）

教案《教材分析》第 6 条就叫**"分层练习设计，循序渐进巩固"**，而且分好了三层：

> 基础层：一步填空、列式，巩固核心公式；提高层：两步归一、归总应用题；
> 拓展层：自主编题、生活估字数、开放性提问

同一份教案里还有两句决定了模板里"每一步问什么"：

> **重视双向推导**：不只是记忆总价 = 单价 × 数量，课堂活动引导逆向推导求单价、数量、速度、时间
> **解题方法多样化**：归一、归总问题均给出两种解题思路

| 教案的层 | 本项目 | 模板 |
|---|---|---|
| 基础层：直接套核心公式 | 基础 0.40 | `T-0501-A` 求总价、`T-0502-A` 求路程、`T-0503-A` 先求一个多少元 |
| 提高层：逆向 + 两步 | 巩固 0.50~0.55 | `T-0501-C/D` 由总价求单价/数量、`T-0502-B/C` 求速度/时间、`T-0503-B` 归总 |
| 拓展层：条件要自己整理 | 挑战 0.62 | `T-0502-D` 时间给的是分钟要先换算、`T-0503-C` 归一之后还要算找回多少钱 |

**"拓展层：自主编题 / 开放性提问"这一层没做**。原因不是省事：这套系统的诊断
靠的是"每个选项都对应一个真实错因"，自主编题和开放提问没法判分，
硬塞进"挑战档"只会变成一堆不能产生诊断数据的题。

### 第四单元 两、三位数乘两位数

《积的变化规律》一课的教学目标写的就是这个知识点该分几层：

> 学生能正确计算多组乘法算式的积，自主发现规律：**两个乘数同时乘（或除以）相同的数（0除外），
> 积乘（或除以）这个数的平方**；能运用规律快速填表、推算积

课的一开始先复习旧知（"一个乘数不变，另一个乘数乘几，积就跟着乘几"），
再推例 1 的表格（从左往右 / 从右往左各说一遍），课堂活动另有一题"一乘一除，积不变"。
教后反思里还有一句对我们最要紧的话：

> 对话环节要**多兼顾计算薄弱学生**，多向**基础弱的学生提问简单计算、表层观察问题**

| 教案的环节 | 本项目 | 模板 |
|---|---|---|
| 旧知：一个乘数变，积跟着变一回 | 基础 0.38 | `T-0405-A` |
| 例 1 表格：从左往右，两个都乘几 | 巩固 0.50 | `T-0405-B` |
| 例 1 表格：从右往左，两个都除以几 | 挑战 0.60 | `T-0405-C` |
| 课堂活动：一乘一除，积不变 | 挑战 0.66 | `T-0405-D` |

这一族的**答案永远是程序直接乘出来的 `askA × askB`**，孩子却只能用规律推。
测试里钉了三条：`expect === askA*askB`、基准步 `refA*refB`、
以及"按黑板那条规律推一遍必须落在同一个数上"——教错的规律比不出题更糟。

《乘数末尾有 0 或中间有 0 的乘法》一课，教案给的分层是：

> **分层实操训练：分层设计基础口算、竖式书写、进位专项、规律拓展练习**

对应的正是 04-01（口算）／04-04（竖式补 0）／04-03（中间的 0 不能跳过：
`0×8=0，必须算，不能漏掉`）。

v2.8 给 04-03 补了"基础口算"那一层：`T-0403-C`（`302 × 3`，难度 0.36）。
原来这个知识点最浅的一道就要 `306 × 13`——那是把"0 也要乘"和"两位数怎么拆成两部分"
两件事一起压上来。教案那句"必须算，不能漏掉"说的是**一件**事，所以乘数先退成一位数，
并且刻意让个位、百位乘完都不满十（不进位）：一有进位，`0 乘几得几` 和进位就混在一起，
错因归不到"0 占位"上了。两种错法各有标签：`MID_ZERO_SKIP`（跳过这一位）和新加的
`ZERO_TIMES_ANY`（以为 `0 × 3` 还得 3）——**它们的教法是两句话**，
前者要教"每一位都要乘到"，后者要教"0 乘任何数都得 0"。
这也是新加方法「每一位都要乘」的理由：它和「盯住 0」长得像但意思相反，
末尾的 0 可以最后补回来，中间的 0 就占在那个数位上，跑不掉。

同一轮 04-06 乘法估算补了 `T-0406-E`（`67 × 3 ≈ ?`，难度 0.38）。
这一档和巩固档的差别**只在凑整几个数**：两位数 × 一位数，一位数没什么可看的，
所以只动一个因数。也正因此，这一档不许出现 `HALF_ROUNDED`（只凑整了一个因数）这个错因——
在这儿它就是正确做法，拿它当错误会冤枉人。测试专门盯着这一条。

### 第六单元 长方形、正方形的面积

《面积的意义》一课的教与学建议第 1 条原话：

> **分层设计，兼顾基础巩固、变式拓展与实践探究**

| 教案的层 | 本项目 | 模板 |
|---|---|---|
| 基础巩固：公式直接套、进率本身 | 基础 0.38~0.40 | `T-0601-A`、`T-0602-A`、`T-0604-E`（1 平方米 = ? 平方分米） |
| 变式拓展：反过来求边长、跨一级换算 | 巩固~挑战 0.48~0.66 | `T-0601-B/C`、`T-0604-A/B/C/D` |
| 实践探究：量一量数学书封面、估计教室面积 | **没做** | 需要动手量、拍照上传，纯前端 + 错因探针这条路走不通；课本上这些活动该由孩子拿尺子真的做 |

教案自己也点了这一层的难点：

> 组合图形一题提供多种解题路径，鼓励一题多解 …… 对估算结果不唯一的道理讲解不够透彻

组合图形的割补需要画图，同样没做。

### 第七单元 条形统计图

《单式条形统计图（1）》第 4 条教与学建议，把问题分成了三层，
这一条几乎可以照抄成分级定义：

> **分层设计问题，落实数据分析。**
> **基础问题**：读取数量、求总数、求差值；**提升问题**：哪组最多 / 最少、相差最大；
> **开放问题**：你发现什么规律？数据说明什么？

| 教案的层 | 本项目 | 模板 |
|---|---|---|
| 基础问题（读一栏是多少） | 基础 0.42 | `T-0701-A` |
| 提升问题（最多 / 最少、相差） | 巩固 0.46 / 0.56 | `T-0701-B/C` |
| 求总数（要先"一格 × 几"再全加起来） | 挑战 0.62 | `T-0701-D` |
| 开放问题（数据说明了什么） | **没做** | 同"自主编题"，没有可判分的错因 |

注意教案把"求总数"列在**基础问题**里，而本项目把它放在了挑战档 0.62。
这是有意的一处下调判断：本项目的图**一格代表多个单位**（`unitPerCell`），
求总数要四栏分别"格数 × 进率"再相加，漏一栏是这一题最常见的错。
教案那份是按"一格代表 1 个"说的，那确实是基础问题。
**同一个词在两份文档里指两件事时，以题面的真实步骤数为准。**

### 第一单元 万以上数的认识

近似数一课的板书是"省略万位，看千位"，当堂就有正向的两题；
教后反思里的两条薄弱点直接变成了档位依据：

> 部分学生容易**混淆整万数改写（使用等号）与求近似数（使用约等号）**
> 少数学生**找不准尾数最高位**，遇到数位较多的大数时容易数错数位
> 后续……增加**对比辨析**专项练习，设计**分层数数**小游戏强化数位识别

于是这一知识点分成：

| 层 | 模板 | 说明 |
|---|---|---|
| 基础 0.40 | `T-0106-E` | 关键位刻意避开 4 和 5，先把"舍 / 进"这件事本身站住 |
| 巩固 0.52 | `T-0106-H` | **改写 vs 求近似数的对比辨析**（= 还是 ≈），v2.8 新增，见下 |
| 巩固 0.55~0.62 | `T-0106-A/B/C` | 正常四舍五入，含亿位、含大数位 |
| 挑战 0.60 / 0.68 | `T-0106-F/G` | 倒推"约是 35 万，这个数最大 / 最小是多少" —— 同步卷里的 ★ 题 |

倒推那两题的错因探针是这一轮新加的（`MAXMIN_SIDE`、`BOUND_OVER`、`BOUND_UNDER`、
`COPY_APPROX`），因为它们各有各的教法：**搞反最大/最小**、**边界跨过去一格**、
**把 35 万直接抄成 350000** 是三件事。测试要"往最大挪 1 或往最小挪 1 都必须破"，
否则题目自己就是错的。

改写与近似数的**对比辨析**（= 还是 ≈）是教案反复强调的易错点，v2.8 做成了 `T-0106-H`：
一道题里同时给一个整万数和一个非整万数，让孩子挑出"两个符号都用对"的那一句。

> 710000 改写成用「万」作单位的数，766808 省略万位后面的尾数求近似数。
> 下面哪一句话把两个符号都用对了？
> · 710000 = 71 万，766808 ≈ 77 万 ←对
> · 710000 ≈ 71 万，766808 = 77 万 ←`REWRITE_VS_APPROX`（改写不敢写等号，近似反倒写了）
> · 710000 = 71 万，766808 = 77 万 ←`REAL_EQ_MIX`（省完尾数还以为两边相等）

这道题有两处设计是**先想清楚才会写成这样**，改之前请先读代码上的注释：

1. 关键位固定取 5~9（近似值必然往前进 1）。要是取 0~4，`384900 ≈ 38 万` 和
   `380000 = 38 万` 两个括号里会是同一个数，选项光看数字分不出对错。
2. 两个错误选项里各埋了一处**数值上就站不住**的半句（把 766808 写成 = 77 万）。
   因为「380000 ≈ 38 万」严格说数值并没错，孩子完全可能来抬杠；
   有了硬伤，这题就只有一种读法。测试里"错误选项必须有硬伤"和"全对的句子只能有一句"
   就是钉这两件事的。

它挂在新增的方法「还是不是那个数」上（判断标准只有一条：换完单位再乘回去，
和原数是不是同一个数）。原来的模板里改写归改写、近似归近似，各练各的，
**没有一道题把两个放在一起比过** —— 这个错因一直没地方被探测到，这才是补它的原因。

### 第二、三单元 角与相交平行

教案的分层靠的是活动形式，不是题目难度：

> **分层设计观察、指认、实操、辨析活动**，循序渐进突破内外圈读数难点
> **分层落实作图规范**，切实突破刻度判断这一核心难点

所以这三块按"指认 → 换算 → 拼/算"排：

- 02-02 角的分类：基础 0.30（大小与边长无关）→ 0.35 给度数 → 0.40 看图 → 巩固 0.46 偏难的角
- 02-04 角的关系与拼角：**基础 0.40 `T-0204-F`（只考"平角 = 2 个直角"这一对）**
  → **探究题 `T-0204-E`（第一次露面必出，不受门禁）** → 巩固 0.45~0.55 → 挑战 0.62。
  基础档刻意**不换那一对**：`T-0204-A/C` 是随机取一对，360 和 180 挨着，
  是这一族里最容易误判的组合，留给巩固档。代价是这一道形态固定、反复见，
  它练的就是那一句口诀 —— 需要多样性的话得再想一层。
- 02-03 角的计算：基础 0.42 直角分两半 → 巩固 0.50 平角 → 挑战 0.58/0.62 周角
- 03-01 平行与垂直：基础 0.38/0.42 判断 → 巩固 0.44 易混的角、0.55 点到直线的距离

量角器读数（内外圈）和画角**没做**：要孩子真的对图上手，纯前端判不了。

## 四、门禁的两条保底（都是踩出来的）

代码在 `js/engine.js`：`unlockedTemplates()` / `openPool()` / `tierAllows()`。

1. **筛完没题就退回全池**：某个知识点只写了高档题时，掌握度低也不能没题做。
2. **退回来的池子里必须有一道非探究题**：`withPlainWork()`。
   这条是当场踩的坑——池子被筛得只剩探究题时，`chooseTemplate` 那句
   "没别的可挑就挑它"会让同一道七步题在一场里出三遍（测试"拼角知识点的第一次露面"抓到的）。

还有一条**探究题不受门禁**（`tierAllows` 第一行 `if (t.intro) return true`）：
它不是考核，是"带你把这个知识点第一次搭出来"。把它锁在高档门外，
等于新知识点第一次露面时反而上不了最好的那道题。

**曾经已知的退让**（v2.8 全部补掉了，留在这儿是为了说清"补在哪一层"）：
下面三个知识点原来最浅的一题就在巩固档，低掌握度时门禁只能靠 `withPlainWork` 捞一道高档题进来。

| 知识点 | 原来最浅 | 补在哪 |
|---|---|---|
| 04-06 乘法估算 | 0.45 | `T-0406-E` 0.38 —— 两位数 × **一位数**，只凑整一个因数 |
| 04-03 因数中间有 0 | 0.56 | `T-0403-C` 0.36 —— 乘数退成一位数，且不进位，只练"0 占位" |
| 02-04 角的关系与拼角 | 0.45（0.40 那道是探究题） | `T-0204-F` 0.40 —— 固定"平角 = 2 个直角"这一对 |

三条补法都是**降低一档的形态**，不是把原来的题改简单：
少动一个因数、少一位乘数、少换一对角。原来那句"估算本身就含两步，去掉一步就不是估算了"
其实说得太早了 —— 去掉的不是两步里的一步，而是把第二步从"两位数乘两位数"换成"乘一位数"，
估算还是估算。

现在有测试直接钉着这件事（`tests/tier2.test.js` 第一条）：
**18 个已实现的知识点，每个都至少有一道基础档的非探究题**。
这条是这一轮真正的收尾 —— 之前它只是文档里的一句话。

## 五、界面上怎么说清楚

- 题目右上角一枚档位徽章：`基础` / `巩固` / `挑战`（绿 / 蓝 / 橙，跟随系统深浅色）
- 巩固、挑战两档在"为什么给你出这道题"下面多一行，把这一档的意思讲给孩子：
  - 巩固：*要绕个弯：反过来想，或者换个样子认它*
  - 挑战：*要把两件事接在一起，或者要把道理说清楚*
- 「掌握度地图」每个知识点后面写**解锁到哪一档**：`只出基础题，练稳了才加档`
  / `已解锁巩固题` / `已解锁挑战题`。**没练过的不显示** —— 那张图上的 0.3 是初始先验，
  显示"已解锁"就是给孩子一个假信号。
