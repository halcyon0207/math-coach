# 数学小教练

错题驱动的四年级数学个性化练习。**纯前端、零部署、零成本**——电脑浏览器打开就能用。

教材：**西师大版《数学》四年级上册**（西南大学出版社，2026 年 6 月第 1 版）。
目前覆盖 7 个单元、18 个知识点、75 个题目模板，题目分**基础 / 巩固 / 挑战**三档
（分档依据和每档出自哪份教案，见 [docs/难度分级方案.md](docs/难度分级方案.md)）。

npm test        # 93 个测试（引擎 42 + 界面冒烟 30 + 难度分级 9 + 基础档补齐 7 + 跨设备同步 5）

### 输入方式

**直接用系统输入法**：答案框是一个真的输入框，手机上点一下就弹出系统数字键盘，
电脑上则直接敲物理键盘 —— `退格`删除、`回车`确认、选择题按 `1` / `2` / `3` 选、`Esc` 退出练习。

（以前是自己画一排数字键，手机上要点半天、退格也不顺手，已经整个去掉了。
用 `type="text"` + `inputmode="numeric"`：iOS 和安卓都给数字键盘，
又不会像 `type="number"` 那样冒出步进箭头、把前导 0 吃掉。）

（点完按钮会把焦点交还页面，否则接着按回车会被浏览器当成"再点一次刚才那个按钮"。
测试里钉了一条。）

### 在题目上直接写写画画

万以上的数（改写、求近似数）最卡的一步是"这到底是几位数、万级在哪"。
页面上给了两个东西，孩子不用再把数抄到纸上：

- **✎ 画一画**——打开后手指直接在题目上画线、圈数位，画错了点「清掉笔迹」。
  笔迹是按"点"存下来的，所以点提示、切步骤之后都还在（换题会自动清掉）
- **看看数位**——把每一位和它的数位（个 / 十 / 百 / 千 / 万…）摊开，
  并按"每 4 位一级"断开。**断开在哪，就是「四位一截」的答案**；
  求近似数时还会把该看的那一位标成橙色

数据默认只存在浏览器的 localStorage 里，不上传任何地方（跨设备同步是可选的，见下）。

### 按单元练

首页先选单元（全部 / 第一单元 / 第四单元），**组卷只在这个单元的知识点里进行**。
一次练一个单元比混着来好：混着出题时名额会被摊薄，哪个单元都练不深。
选过的单元会记住，下次打开还是它。

首页的「做题的方法」和「掌握度地图」同样按单元分组 —— 孩子刚练完哪个单元，
就到那一栏去看。

### 家长报告（需口令 · 时间 · 效率 · 错点）

首页最下面有「家长报告（家长 · 需口令）」入口。第一次进去让家长设一个 4～6 位数字口令，
之后进来都要输这个口令。报告内容：

- **总览**：练了几次、共几题、正确率、累计做题用时
- **每次练习**：几点练的、对了几题、**每题约多少秒**（效率就看这个——明显变慢多半是卡住了）、用了几次提示
- **错误点都在哪**：按知识点列出正确率和"最常错的错因"
- **最近的错题**：原题、错因、有没有用提示
- **导出 CSV**：全部作答记录，可用 Excel 打开
- **清空所有数据**：换孩子用或重新开始，会连同口令一起清掉

这道口令门挡的是三样会坏事的东西：**错题和正确答案**（孩子照着答案抄一遍，等于没练）、
**导出记录**、以及最要紧的**清空数据**（以前"清空所有数据"就在孩子能进的掌握度页上，
点一下再确认一下就全没了，还查不出是谁点的——现在它挪到口令后面）。
口令明文存在这台设备上，**挡住的是孩子顺手点开，不防翻这台设备的外人**；
忘了口令只能清本地数据重来，不做找回。离开报告页解锁即失效，下次回来重新要口令。
数据默认全在本机，不上传（跨设备同步是可选的，见下）。

### 在别的设备上看报告（可选，默认关）

默认这份报告只在这台设备上能看到。要跨设备就在首页「跨设备同步（家庭码 · 需口令）」里
生成一个家庭码，另一台设备填同一个码：

- 孩子在这台设备练完 → 统计自动上传 → 家长在自己手机/平板上打开报告页就能看到
- **语文和数学共用一个家庭码**（一个码管两个项目）。两边数据分开存，不会串：
  数学报告里不会出现语文那台设备的统计，语文清空数据也不会带走数学的记录。
- **家长端不是单独的网址**：同一个网址，首页「家长报告（家长 · 需口令）」进去。
  口令各台设备各设一次（它只存在那台设备上）。
- **在自己手机上看报告也不是空的**：报告把本机和各台设备上传的记录合在一起显示
  （场次、正确率、错题、按知识点的错误点，都合并）
- 不用点同步：练完自动上传，打开报告页自动拉取；**平时完全不联网**
- 云端**只留每台设备的最新一份统计**（覆盖写），不存全量历史 —— 全量一直在本机
- 家庭码是唯一一道门，知道码的人能看到练习情况

> 语文那边还能跨设备**批改**（孩子平板写、家长手机批）；数学是程序自动判分，
> 没有"待批改"这一环，所以只做报告只读。

## 为什么这样做

### 1. 出题、判分、找错因、算掌握度，全部是程序

**大模型碰不到答案。** 数学答案一旦出错，家长对工具的信任是一次性归零的，
所以这一期核心链路上没有一次模型调用。副作用是成本几乎为零、离线可用。

### 2. 干扰项 = 错因探针

选择题的错误选项不是随机造的错数，而是按孩子真实的错误路径反推出来的：

```
125 × 88 = ?
  11000  ✓
  80000  ← 拆成 125×80×8，把和误当积      → 拆分逻辑错误
  10000  ← 拆成 125×8×10，漏掉 11         → 拆分不完整
   1100  ← 数位错位                        → 计算与数位错误
```

孩子选了哪个，系统就直接知道他想错了哪一步——不需要 OCR，不需要模型猜，
**错因是自证的**。

配套的克制原则：**拿不准的干扰项不要硬凑**。宁可有 3 个选项，也不要污染归因数据。

四年级"计算不仔细"的错误模式其实是收敛的，就这几类：

| 标签 | 说明 |
|---|---|
| `ZERO_LOW` / `ZERO_HIGH` | 末尾的 0 数少了 / 数多了 |
| `FORGOT_ZEROS` | 有效部分算对了，忘了补末尾的 0 |
| `DIGIT_SHIFT` | 乘 20 和乘 2 混了，积的数位错 |
| `CORE_CALC` | 去掉 0 之后的那步乘法就算错 |
| `SPLIT_SUM` | 拆开之后合起来算错 |
| `ROUND_WRONG` | 凑整凑错了 |

刻意避开的词：**"粗心""不认真""马虎"**——这些词对孩子没有任何可操作性。
测试里有一条专门盯着这件事。

### 2.1 题面不能有第二种读法（踩过的坑）

错因探针有个前提：**题目的说法必须只有一个意思**，否则归因会脏。

真实踩过的坑，`500 × 60` 那道题的第 ② 步：

```
原问法：两个因数末尾一共有几个 0？      答案 3
```

但 `500 × 60 = 30000`，结果末尾明明是 **4 个 0**。于是这句话有两种读法：

- 两个**因数**末尾一共有几个 0 → 3
- 两个数相乘，**结果**末尾一共有几个 0 → 4

答 4 会被判错，还会被归到「末尾 0 数多了」这个错因上 ——
**一个理解得更细的孩子反而被记成想错了**，错误数据就这么进了库。

改法是把问法**点名到具体的数**上，去掉"结果"那一种读法：

```
新问法：500 和 60，末尾一共有几个 0？    答案 3
```

同时还有一个更隐蔽的点要跟孩子说明白：`5 × 6 = 30` **本身就带一个 0**，
所以补 3 个 0 得到的结果末尾是 4 个 0。不解释，谁看都会以为系统数错了。
现在这种情况讲解里会自动多出一句：

> ④ 注意：30 末尾本身已经有 1 个 0，所以 30000 末尾一共是 4 个 0 —— 这不是多补了。

测试里有一整组专门守这件事（`题目与答案的对应性`），它不只验算术，还验：

- 数 0 这一步有没有点名两个因数（并且不许出现"两个因数"这种歧义写法）
- 「补 N 个 0」和最终答案能不能串成一条自洽的链（`final === core × 10^N`）
- 凑整题的答案是不是真的"最接近"，以及是不是平局（平局就是废题）
- 每一个设计出来的干扰项都必须带错因标签，不许落到 `OTHER`

### 3. 阶梯题，同时解决两件事

一道题拆成有先后顺序的步骤：

```
[拆开看]  250 × 40 = ?

① 25 × 4 = ?                       ← 辅助步骤
② 两个因数末尾一共有几个 0？        ← 辅助步骤（最薄弱时才显示）
③ 250 × 40 = ?                     ← 核心步骤（永远显示）
```

- **手机上输入友好**——每步一个小数字，不需要在手机上写竖式
- **难题变简单**——"不愿思考"很多时候不是懒，是不知道该从哪一步开始

支架档位会随练习情况调整，但**撤得非常保守**（这一条改过一次，见 3.1）：

| 条件 | 档位 |
|---|---|
| 这个知识点还没做满 5 题 | 全拆（3 步） |
| 正确率不到 75% | 全拆 |
| 做满 5 题、正确率达标 | 拆一半（2 步） |
| 做满 10 题 **且** 正确率 ≥ 85% **且** 掌握度 ≥ 85% | 才只问最终答案 |

### 3.1 支架为什么不能"答对一次就撤"（改过的坑）

原来的写法是只看掌握度：`<0.45` 全拆，`<0.75` 拆一半，再高就不拆。

而 BKT 在"填空题基本蒙不中"的前提下（`P_G = 0.05`），**一道题答对就能把掌握度从 0.30 推到 0.91**——
于是第二次练习整场都不拆了。表现出来就是"**题目突然没有步骤了**"。

撤早了代价很大：这个孩子本来就不愿碰难题，支撑一撤，他面前就是一道整题，直接退回"不做了"。

现在撤支架看的是**证据够不够、稳不稳**，不是一次答对。另外掌握度本身也加了一道阻尼——
前两次作答按证据量打折，因为 0.30 这个先验本来就是拍的，不该让第一道题就把它推到 0.9。

实测三种情况下的撤退节奏（每场 10 题）：

| 场景 | 第 1 场 | 第 2 场 | 第 3 场 | 第 4 场 |
|---|---|---|---|---|
| 全部答对 | 10 题全拆 | 5 题 3 步 + 5 题 2 步 | 9 题 2 步 | 才降到 1 步 |
| 每场错 2 道 | 10 题全拆 | 5 题 3 步 + 5 题 2 步 | 1 题 3 步 + 9 题 2 步 | 仍有 2~3 题全拆 |
| 每场错 4 道 | 10 题全拆 | 10 题全拆 | 7 题 3 步 | 7 题 3 步 |

测试里有两条回归钉着这件事：`做完一整场之后，支架不会整场消失`、`答错较多时，支架应当保持全拆`。

### 4. 数量级校验：训练"检查"这个动作

对"计算不仔细"的孩子，多刷 50 道题不如训练一次检查习惯：

```
老师算：348 × 25，你答 870
程序：估算 350 × 25 ≈ 8750，位数对不上
     → "结果的位数好像不对，要不要再检查一下？"
```

不告诉他答案，只告诉他一件事：**算完要回头看**。提示语里刻意不含任何数字
（测试里有断言守着）。

### 5. 「提示后正确率」区分"不会"和"不仔细"

| 表现 | 判定 | 干预 |
|---|---|---|
| 一答就错，给提示后立刻做对 | 不仔细 | 不加练，进"估一估"训练 |
| 给完整提示后仍然错 | 真的不会 | 回到前置知识点从基础补 |
| 3 天后重做仍然对 | 真掌握 | 降低出现频率 |

只有"对/错"两个维度时，这两种情况长得一模一样，系统会误判——
给不仔细的孩子狂刷计算题，是最消耗耐心也最没效果的做法。

掌握度用 BKT 更新，其中 `P_G`（蒙对概率）按题型和是否用了提示区分：
**选择题按这一题实际的选项数取 `1 / 选项数`**（两个选项就是 0.5）、
填空题 0.05、**用了提示后 0.40**。所以提示后做对的涨幅明显更小。

> 这里改过一个不小的坑：原来选择题的蒙对率写死 0.25（假设 4 个选项），
> 而实际生成出来的题绝大多数是 2~3 个选项。同样答对一题，按 0.25 算掌握度会
> 涨到 0.685，按 0.5 算只到 0.548 —— 蒙对了被当成"有把握"记账，
> 支架就会撤早。这和本文件 3.1 那条是同一类错误，只是换了个方向。

### 6. 组卷：前三题必须让他赢

对"难题不愿思考"的孩子，直接上薄弱点会把他推走。所以固定结构：

| 位置 | 类型 | 目的 |
|---|---|---|
| 第 1–2 题 | 热身（难度 ≤ 0.45） | 建立"我能做"的状态 |
| 中间 7 题 | 没练过的先各占 1 题（保证露面），名额有剩再各补 1 题；其余按薄弱程度轮流补，最弱的占两个位置 | 真正要练的 |
| 中间末尾 2 题 | 抗遗忘（挑已练过、且不是最薄弱的） | 隔几天再回来做一次 |
| 第 10 题 | 挑战（**已解锁**的题里最难的一道） | 唯一一道难的 |

后面两条约束是踩坑之后加的：

- **没练过的知识点必须被安排到。** 之前"薄弱"和"抗遗忘"两档把 10 个名额占满，
  一次都没练过的「乘法估算」**一整场都没出现过**——孩子根本没机会看到它。
- **抗遗忘不吃薄弱点的名额。** 挑替换位置时跳过最薄弱的那个知识点。

测试里有一条 `每个知识点在一场练习里都至少出现一次`，连跑 40 场检查覆盖。

每道题都显示 **「为什么给你出这道题」**，把系统的判断摊开给他看：

> 热身题。这两道比较简单，先把状态找回来。
> 你在「因数末尾有 0 的乘法」上错过了 3 次，再练一下。
> 最后一道稍微难一点，试试看 —— 做不出来也完全没关系。

#### 做过的题会不会"又是这道题"？

一个单元就 10 道题，第二次练是不是把第一次的原样再来一遍？这件事分三层，各说各的：

- **知识点**：第二场优先排「还没练过的 / 到期该复习的 / 最薄的」，所以两场的知识点
  很少是同一批 —— 这是刻意的互补，不是随机。
- **题型**（同一知识点下的不同考法）：出题时避开**这一场已经出过的**，也避开**最近两场做过的**
  （取最近 20 条作答记录里的模板 id）。所以同一场 10 道题不会撞题型。
  但刚来的孩子只开放基础档，而不少知识点在基础档里只有一种题型 —— 换无可换时，
  允许同一个题型换新数字再来一遍。这种情况会随着掌握度上升、档位解锁而消失：
  每个知识点其实有 2～8 种题型，**全解锁后相邻两场可以做到完全不撞题型**。
  退让是有意的：宁可同一个题型再练一遍，也不为了"不重复"去抓一道难度不对的题。
- **具体的题目**：每一道都是现场生成的，数字是新的。**同一个题型 ≠ 同一道题。**

有两条测试钉着它：`同一场里不撞题型`、`相邻两场的题型不重复（各档都解锁之后）`。

### 7. 其他几个刻意的选择

- **没有倒计时**——制造压力，也会干扰"到底会不会"的判断
- **有「我要提示」，没有「跳过」**——跳过是逃避，提示是前进
- **提示用了不扣分、不批评**——一旦有惩罚，孩子宁可乱猜也不点，机制就废了
- **答对不放烟花、不给积分**——夸张的外部奖励会挤占内在动机，撤掉后掉得更狠
- **不做排行榜**——小学阶段的横向排名会伤到暂时落后的孩子
- **方法有名字**——「盯住 0」「拆开看」「先估后算」。四年级的孩子还不会自发总结方法，
  命名之后他才可能把它迁移到别的科目。题目上不只显示方法名，还把它那三步列出来

### 8. 方法挂在"题型"上，不是挂在"知识点"上

这一条是改出来的。最初我把方法挂在知识点上，一个知识点一个方法，结果是错的：

- `20 × 30`（整十整百口算）→ 先算 2×3，再补 2 个 0
- `250 × 40`（因数末尾有 0）→ 先算 25×4，再补 2 个 0

**这两步完全一样**，却被我标成了两个不同的方法名。孩子看到两个名字做同一件事，只会更糊涂。

真正需要用「拆开看」的只有一种题型——乘数末尾没有 0，补 0 那招用不上：

```
250 × 24 = ?      拆成 250×20 + 250×4 = 5000 + 1000 = 6000
```

所以方法搬到了模板这一层：

| 模板 | 题型 | 方法 |
|---|---|---|
| `T-0401-A/B` | 整十整百相乘 | 盯住 0 |
| `T-0404-A/B/C` | 因数末尾有 0 | 盯住 0 |
| `T-0404-D` | 乘数末尾无 0，要拆 | 拆开看 |
| `T-0406-A/B` | 估算 | 先估后算 |
| `T-0105-A/B` | 改写成万 / 亿 | 四位一截 |
| `T-0106-A/B` | 求近似数（万 / 亿） | 看下一位 |

副产品是首页会显示"**同一个方法用在不同知识点上**"——这本身就是值得让孩子看见的事。
测试里有一条专门盯着这个区分（`方法挂在题型上，不是挂在知识点上`）。

### 9. 难度分三档，高档要解锁 —— 而不是随机撒难题

孩子的原话是"全是基础题，练几次就没意思了"；但同一句话后面紧跟的是"还是要先夯实基础"。
这两件事不冲突，冲突的是**随机出难题**：最先碰到难题的永远是错得最多的那个孩子，
他被打击、掌握度掉下去、支架撤得更快，分级反倒变成惩罚。

所以三档做成了**闸门**（`js/knowledge.js` 的 `TIERS`）：

| 档 | 是什么 | 什么时候出场 |
|---|---|---|
| 基础 | 和课本例题一样，一步一步就能算出来 | 一直出 |
| 巩固 | 要绕个弯：反过来想，或者换个样子认它 | 这个知识点掌握度 ≥ 0.45 |
| 挑战 | 要把两件事接在一起，或者要把道理说清楚 | ≥ 0.70 |

档位**不写在模板上**，由模板本来就有的 `difficulty` 查出来 —— 只有
一份难度数字。再加一次"这是基础题"的标记，两份账迟早打架。
组卷时门禁落在**题池**上（`Engine.unlockedTemplates` / `openPool`），
而不是"随机数决定难不难"。已有的连续自适应难度（连错降、连对且掌握度高才升）
继续在档内挑题，两者各管一层。

保底规则有两条，都是这一轮踩出来的：筛完没题就退回全池；
退回来的池子里**必须还有一道非探究题**（否则 `chooseTemplate` 的退让
会让同一道七步探究题在一场里出三遍）。探究题本身不受门禁 ——
它不是考核，是"带你把这个知识点第一次搭出来"。

界面上三处说明：题目右上角档位徽章、"为什么给你出这道题"下面一行这一档在练什么、
掌握度地图里写"练稳了才加档"。**没练过的知识点不显示解锁状态** —— 那个 0.3 是初始先验，
显示"已解锁"是给孩子假信号。

每一档凭什么这么分、对应哪份教案的原话，写在
[docs/难度分级方案.md](docs/难度分级方案.md)（条形统计图那一课的教案
"基础问题 / 提升问题 / 开放问题"几乎可以照抄成分级定义）。
里面原本记了三处**已知退让**：乘法估算、因数中间有 0、拼角，
它们最浅的一题就在巩固档，低掌握度时门禁只能放行。
v2.8 把这三处补掉了，而且现在有一条测试直接钉着它——
**18 个已实现的知识点，每个都至少有一道基础档的非探究题**。
这句话在 v2.7 之前只是文档里的一个承诺。

两件事合起来才是"往后走"：前者是**用规律推乘法**（五年级算 `25×16` 要简算、
六年级学商不变规律都靠它），后者是**两步应用题的第一批**，也就是试卷上最后那道大题的样子。

**什么样的知识点才配进图谱**：本系统的地基是"干扰项 = 错因探针"——
选项必须能反推出孩子错在哪一步。上面每一条的答案都由程序算得出，
干扰项按真实错误路径反推（漏补 0、看错数位、四舍五入方向反了……）。
而读数、写数、数位顺序表、大小比较属于记忆与概念型内容，
硬凑成"错因探针"只会污染归因数据，所以一直没纳入——这不是没做完，是刻意不做。

17 个方法（`Knowledge.METHODS`）挂在**题型**上而不是知识点上：
同一个知识点里的不同题型可以走不同方法（比如 04-04 里既有"盯住 0"也有"拆开看"，
04-03 里"拆开看"算大题、"每一位都要乘"专管中间那个 0 到底要不要写）。

**溯源**不是让模型猜根因，而是：这个知识点薄弱 → 查它的前置 → 用几道前置题去确认。
没进图谱的知识点不会出题。

## 加一个知识点要做什么

1. 在 `js/knowledge.js` 里加一条（含 `prereq` 和方法），把 `implemented` 设为 `true`
2. 在 `js/templates.js` 里加 **至少 2 个** 模板（只有一个的话，同一个知识点连着出两题必然重复）
3. 每个模板要做到：答案由程序算出、干扰项对应真实错误路径、有 `hint` 和 `teach`
4. **三档至少铺到两档，而且必须有一道 `difficulty ≤ 0.42` 的非探究基础题。**
   这条现在是**测试**，不是文档里的叮嘱：`tests/tier2.test.js` 第一条会遍历所有
   `implemented` 的知识点，少一道基础题就红。v2.7 上线分级时就有三个知识点漏在这条外面
   （乘法估算最浅 0.45、因数中间有 0 最浅 0.56、拼角最浅的正经题 0.45）——
   掌握度低的孩子一进场，池子里一道基础题都没有，门等于关着，
   只能靠 `withPlainWork` 那两道保底退让。v2.8 补齐了这三处。
   另一条相关的老检查（`npm test` 里 `闸门不许把出题夹死`）还在：
   退让能保住题量，但档位就没意义了
5. 每道高档题问自己一句：**教案里哪句话说明这是"下一层"？**
   答不上来就先别加 —— 难度数字是手调的，没有依据的档位会把闸门变成随机
6. `npm test` —— 有一条测试会遍历所有模板各生成 400 次，验证答案等于程序算出的乘积

**工作量的大头是设计干扰项，不是写代码。** 如果某个知识点你想不出有意义的错误路径，
说明它可能不适合做选择题诊断，需要换题型（比如填空题 + 数值比对）。

## 已知限制

- 覆盖第一到第七单元共 18 个知识点、75 个模板。第八单元是总复习，刻意不单独出题
- **基础档已经铺满，但补齐的那几道形态是固定的**：`T-0204-F` 只考"1 个平角 = 几个直角"
  这一对（周角和 360/180 挨着，留给巩固档），所以同一个知识点里它反复出现就是同一句话。
  换来的是"掌握度低时确实有题可出"，代价是低档的多样性 —— 要不要再铺一两个数字对，
  记在 [docs/难度分级方案.md](docs/难度分级方案.md) 第七节
- **教案里有分层、我们没做的那几层**：自主编题、"数据说明了什么"的开放提问、
  面积实践探究（量数学书封面）、组合图形割补、量角器读数与画角。
  共同原因是这套系统靠"每个选项对应一个真实错因"做诊断，
  这些题型要么没法判分、要么要孩子真的动手操作，硬塞进高档只会产生一堆没有诊断价值的题
- 每个知识点只有 2～8 个模板，最薄的（06-02 正方形的面积）只有 2 个，连着练还是会撞题
- 只判最终答案，不判过程（画一画、阶梯辅助步骤的错因会记，但不判书写）
- 没有启发式讲解对话（二期）；现在的"讲解"是模板里预写的固定步骤
- 错题只在家长报告里列最近 15 条，孩子端没有"错题重做本"
- 要挂在网上得先 `npm run serve` 或部署到静态托管；直接双击 `index.html` 也能用，
  但那样每个文件夹都是独立的数据（浏览器按路径隔离 localStorage）
- 版面在 1040px 以下会退回单栏。如果要更宽的屏幕布局（比如三栏），还需要再调
